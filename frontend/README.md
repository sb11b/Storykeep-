# Storykeep web client

Next.js UI for the personal RSS archive. Run it from the repo root instructions in `../README.md`.

```bash
npm install
API_ORIGIN=http://127.0.0.1:18741 npm run dev
```

The app proxies `/api/*` to the FastAPI server.

## Install as a desktop app (PWA)

StoryKeep is installable as a windowed desktop app in Chrome or Edge
("Install app" / "Install StoryKeep…" in the address-bar menu, or the install
icon in the URL bar). Once installed it opens in its own standalone window
with no browser chrome. Safari on iOS/macOS can add it to the Home Screen
via Share → Add to Home Screen (uses `apple-touch-icon`).

The manifest is generated by the App Router (`src/app/manifest.ts`); the
icons in `public/icons/` are generated by
`scripts/generate_pwa_icons.py` (requires Pillow; rerun after a palette
change).

## What works offline

The dependency-free service worker (`public/sw.js`, registered in production
by `src/components/pwa-register.tsx`) implements four strategies:

- **App shell + static assets** (`/`, `_next/static`, icons, manifest,
  fonts): cache-first, precached on install.
- **Junior API GETs** (`/api/v1/junior/*` — jobs, memory, and the rest of
  the library): stale-while-revalidate. Cached responses are served
  instantly and refreshed in the background, so the library keeps working
  with the data you last saw.
- **Mutations** (POST / PATCH / PUT / DELETE): network-only, never cached —
  an offline write fails loudly instead of pretending to succeed.
- **Navigations**: network-first, falling back to the cached shell and the
  static `/offline` page.

A small offline indicator appears at the bottom of the window when the
network is down. No data is ever fabricated for offline use.

## Static export and the future Tauri wrapper

`NEXT_OUTPUT=export npx next build` produces a fully static `out/`
directory (manifest, icons, and `sw.js` included). That same cache is what
will make the planned Tauri desktop wrapper work offline — the static
export is the build target both paths share.
